TPM chatbot — local test

Stands in for a WordPress page. The bubble is bottom-right. If it works here it will work on the real site.

Open this at http://localhost:5173/demo.html. Double-clicking the file gives an origin of null and CORS blocks every request.

Three things must be running

docker run -p 6333:6333 -v "$(pwd)/qdrant_storage:/qdrant/storage" qdrant/qdrant

# in the API repo
$env:ALLOWED_ORIGINS="http://localhost:5173"
uv run uvicorn app.api:app --reload --port 8001

# in this repo
python -m http.server 5173

Check the API first: curl.exe http://localhost:8001/health should report points: 1764.

If something looks wrong

  • Bubble appears, every message errors — open the console with F12. A CORS message means ALLOWED_ORIGINS and the port you served this page on disagree.
  • Long pause then an error — the API is up but OpenAI is not responding. Check the uvicorn terminal.
  • Sources panel on a greeting — the tool-choice rule in chat.py's system prompt is not being followed.
  • Answers with no citations on TPM questions — it is answering from memory. Watch for searched=False in the uvicorn log.
  • Nothing at all — hard refresh with Ctrl+Shift+R. The browser caches tpm-widget.js aggressively.
